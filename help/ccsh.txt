ccsh: ccsh, a small POSIX-style shell for CraftOS

  ccsh
      an interactive shell
  ccsh -c 'commands' [name [arg...]]
      run one command line
  ccsh script [arg...]
      run a file of commands

ccsh runs inside the stock CraftOS shell and has it find and run the programs (the same path, aliases and directory; cd, alias and set work as they always do).  What it adds:

  a | b | c
      pipes.  Each command runs to its end, then the next reads what it wrote: nothing streams, so `a | head` still runs all of a.
  < f   > f   >> f
      redirects; also 2> f, 2>> f, 2>&1, >&2, n>&-. /dev/null works for reading and writing.
  a ; b   a && b   a || b   ! a
      and a newline is a ;
  'single' "double" \x
      quoting; # starts a comment.  A line ending in \, |, &&, || or inside quotes goes on to the next.
  X=value $X ${X} ${X:-default} $? $# $1..$9 $@ "$@" $* $$ $! $0
      variables.  $PATH is the shell's path (setting it changes the path), $PWD its directory and $HOSTNAME the computer's label (its ID if it has none).  $! is the last & job's process ID.
  export X  X=1 cmd
      the environment.  Programs read it with os.getenv("X") (and change their own copy with os.setenv(name, value), list it with os.environ()): the exported variables (PS1 is one), PATH, PWD and HOSTNAME, and for one command its own X=1 words.  A ccsh run from ccsh starts with them as exported variables; `env` shows them.
  PS1
      the prompt, an exported variable: \h (label, or ID), \w (the directory), \W (its last part), \i (the ID), \$, \n and \\: PS1='\h \W\$ '.  It starts as '\h:\w\$ ' ("label:/dir$ ") on a computer with a label, '\w\$ ' without one, unless the environment brought one.
  *  ?  [abc]  [!a-z]
      globs; a name starting with a dot only matches an explicit dot, and the fileserver's member disks (/disk, /disk2... with /jbod mounted) only a pattern that starts with a plain character (disk*, not *). No match leaves the word as is.
  $(cmd)  `cmd`
      command substitution (in a subshell).
  if a; then b; elif c;
      then d; else e; fi
  while a; do b; done
      until a; do b; done
  for x in words; do b; done
      (no `in words`: "$@")
  case word in pat|pat) a;; (pat) b;; *) c;; esac
      (globs, as in names)
  { a; b; }
      a group; ( a; b ) a subshell: its variables, functions, exit and directory are its own
  name() { body; }
      a function (function name { body; } too): $1... are its arguments; return [n]; local name[=value] until it returns
  break [n], continue [n] out of, or on round, the n'th loop out.
      Any of these can be piped and redirected as a whole: for f in *; do ...; done | sort, while read l; do ...; done < file.  They span lines at the prompt.  A loop lets the rest of the computer run every 100 turns, and Ctrl+T stops it.
  a &
      a background job: the line goes on while it runs.  It gets its own copy of the variables and every event but the keyboard's and the mouse's.  At the prompt, Ctrl+Z stops the job in front (a stopped job keeps the events it misses for later).
  jobs [-l|-p]          the jobs: [1]+ Running
      sleep 10 &
  fg [%n]  bg [%n]
      a job to the front (waiting for it), or a stopped one carried on in the background.  %n is job n; %% or %+ the latest, %- the one before, %str the one whose line starts so.
  fg prog  bg prog
      as CraftOS's fg and bg: prog in a new multishell tab (shown, for fg), with the environment.
  wait [%n|pid...]
      wait for jobs (all, with none named); their status.  Ctrl+T stops waiting.
  kill [-9] %n|pid...
      end a job as Ctrl+T would; -9 drops it at once. Under init, a pid that isn't a job's is a process's (see ps).
  builtins
      also exit [n], :, true, false, read [-r] name..., shift [n], unset name..., . file, export [-n] name[=value]... and export -p

Not yet: here-documents, $(( arithmetic )) (expr does sums), ~.

At the prompt, ccsh first runs the commands in /.profile (PS1, export...), as `. /.profile` would.  The up and down keys go through the lines typed before, kept in $HISTFILE (/.ccsh_history; unset or empty, none) across sessions and tabs, the last $HISTSIZE of them (1000; 0 keeps none).  Both are shell variables, set before /.profile runs so it can change them.  Leave with exit, or by holding Ctrl+T at the prompt; with jobs left, the first try only warns, and the jobs end with the shell.  Ctrl+T while a command runs stops it, and the rest of the line, with status 130.  A script or -c waits for its background jobs before it ends: they can't outlive it.

A script can start with #!/ccnix/bin/ccsh (the stock shell honours the #! line; under the ROM alone it's #!/rom/ccnix/bin/ccsh), or run as `ccsh script`.

Programs see a pipe or a file as io.input() and io.output().  print, write, term.write and printError are redirected too, so stock programs can be piped: `ls | grep lua`.  ls lays its names out in columns as it would on screen, so `ls | wc -l` counts rows, not files.  Full-screen programs (edit, paint) need the screen: don't pipe them.  While a command runs, _G.POSIX_SH is set (echo leaves > to the shell then).
