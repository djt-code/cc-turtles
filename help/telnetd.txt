telnetd: a telnet server: a shell, or the console, over the network

  telnetd
      serve (run it as a service: see below)

Any telnet client can connect (ours is `telnet`).  After the password, each connection gets a shell of its own, sized to the client's screen: ccsh if ccsh.login is on, else the CraftOS shell; leaving it closes the connection.  With telnetd.attach set to "console" it gets the console instead, whatever runs there (the miner's screen, the farmer's...): what's on the screen is shown, and what's typed goes to it as if typed here, but Ctrl+T doesn't (Telnet's "interrupt process", Ctrl+] then t in our client, does).  The screen goes as ANSI escapes with xterm's 256 colours.

Settings: telnetd.password (what to type at "Password:"); telnetd.open (true: no password at all); telnetd.attach ("console", or "" for a shell each); telnetd.port (23).  It won't start without a password unless telnetd.open is on.  The password crosses the network as typed, as with any telnet.

telnetd needs init, which runs its shells as processes, and the network (`ip up`).  To keep it running in the background:
  service add telnetd telnetd
  service enable telnetd          (at boot)
  service start telnetd
deploy/setup telnetd does all that.  `service status telnetd` shows who has connected.
