network: setting up a network lab (3 computers, 2 networks, a router)

The network stack (`help ip`) joins computers over modems, in layers: frames on a modem channel, ARP, IP with routing, ICMP, UDP and TCP. This sets up two networks with a router between them.

Build it:
  R  the router, A and B the hosts
  A  wired modem, cable to R's left modem
  B  wired modem, cable to R's right modem
Keep the two cables apart: touching, they're one wire. The modems don't need right-clicking (that only shares peripherals); messages cross a cable either way.

Install (HTTP on):
  on R: wget run https://raw.githubusercontent.com/djt-code/ccnix/main/deploy/setup.lua router --autostart router
  on A and B: the same, with just net instead of router --autostart router
Each reboots when done. The network then comes up at every boot (on R with forwarding on, and the router's screen).

Configure (`ip link` lists the modems' names); what's set is kept, and applies at once:
  on R:
    ip addr add left 10.0.1.1/24
    ip addr add right 10.0.2.1/24
    router
  on A (modem on its back):
    ip addr add back 10.0.1.10/24
    ip route add default via 10.0.1.1
    ip up
  on B:
    ip addr add back 10.0.2.20/24
    ip route add default via 10.0.2.1
    ip up

Test, from A:
  ping 10.0.1.1          the router
  ping 10.0.2.20         B, through it: ttl=63
  traceroute 10.0.2.20   1: 10.0.1.1, 2: 10.0.2.20
TCP chat: `nc -l 7` on B, then `nc 10.0.2.20 7` on A and type: the lines show on B, and B's on A. Ctrl+T ends your side; the other's ends when it sees that.
UDP: the same with `nc -u -l 7` and `nc -u 10.0.2.20 7`: the lines go one way, as datagrams.

One cable, with VLANs: chain A, R and B on one cable, and give each network its own VLAN. On R: `ip addr add left.10 10.0.1.1/24` and `ip addr add left.20 10.0.2.1/24`; on A `back.10`, on B `back.20`. Each VLAN is its own channel on the wire, so A and B still talk only through R.

The real network: the ccnix mod (in the repo's mod/) adds a Network Gateway block, the server's way onto a CC network. Cable it to R's modem, give R an address on its network (`ip addr add back 10.0.0.2/24`, the gateway being 10.0.0.1) and `ip route add default via 10.0.0.1`. R's networks then reach the real network through the server, given the gateway's route back to them (`/ccnix route add 10.1.0.0/16 via 10.0.0.2` in game, by an op, where the server allows it). The gateway has two modes, the server admin's choice (`/ccnix` says which):
  NAT    (the mod's default) CC computers reach the outside as the server itself: TCP and UDP work (nc, telnet, DNS); the gateway answers ping, but ping and traceroute go no further: "administratively prohibited" (traceroute shows the gateway as a hop, then !X on the next); private addresses and port 25 are refused; the outside reaches a computer only through a port forward (`/ccnix forward`). `ip dns 10.0.0.1` asks the server's own resolver.
  TUN    a TUN device on the server routes: real addresses, ping, and real machines reach CC computers as the server's routes and firewall allow.

Names: `ip host b 10.0.2.20` on A lets `ping b` work.  With a way out through the gateway, `ip dns 1.1.1.1 9.9.9.9` (a primary and a secondary; one will do) on each computer lets real names work too: `ping example.com`, `nc example.com http`, `host example.com`.  The hosts are looked at first, then DNS; if the primary doesn't answer, the secondary is asked.

Telnet: on B, `wget run https://raw.githubusercontent.com/djt-code/ccnix/main/deploy/setup.lua telnetd`, then `set telnetd.password pick-one` and reboot. On A, `telnet 10.0.2.20` and the password: B's shell, on A's screen. Ctrl+] then q comes back. `set telnetd.attach console` on B shows its console instead (the miner's screen, say).

When it doesn't work:
  ip          what's set, and whether it's up
  ip neigh    the addresses ARP has found
  router      on R: packets in, out, forwarded and dropped, and messages such as "no ARP answer"
  ping says   "net unreachable": a router has no route; "administratively prohibited": a filter, or a NAT-mode gateway (no ICMP past it; it answers ping itself); "host unreachable": nobody answered ARP (wrong address, or not up); "time to live exceeded": routers pass it round in a loop
  host says   "no DNS servers": `ip dns` sets them; "Temporary failure": no server answered (each one's reason in brackets: can the computer ping it?)
